# 日报生成流程

这个 skill 的最短闭环是：

`读取原始新闻表 -> 基础过滤与去重 -> 大模型筛高价值事件 -> 全文阅读 -> 按模板生成 signal 日报 -> 更新日报文档 -> 生成早报导读`

## 两类入口

### cron 正式入口

- 默认读取过去 24 小时
- 生成正式日报
- 发到目标群
- 适合固定晨报

### 飞书私聊入口

- 可临时指定时间范围
- 可只试跑不正式发群
- 默认发给当前发起人
- 适合验证模板、语气和筛选效果

如果产出看起来像资讯摘要、筛选结果明显不对，优先回看：

- `references/gotchas.md`

## 推荐执行顺序

1. 从飞书原始新闻表读取本轮日报对应的数据。
2. 查询层优先按文本字段 `报道窗口键` 过滤，例如 `2026-03-18-0900`；如果该字段不可用，再退回按发布时间窗口过滤。
3. 再按 `原文链接`、`标题哈希 + 发布时间` 去重，并排除时间不可信或明显噪声记录。
4. 由大模型筛出值得进入正文的高价值事件，不要把所有新闻都写进日报。
5. 对高价值事件逐条阅读全文。
6. 由大模型按模板生成 signal。
7. 更新当天日报文档。
8. 基于日报文档内容生成早报导读。
8. 输出一段简短过程日志，说明筛选路径和结果。

## 高价值事件默认标准

下面这些默认要阅读全文：

- 官方博客、官方公告、研究发布
- 多个来源都在提的热点事件
- 监管、安全、融资、并购、重大产品更新
- 需要写“判断更新”或“待验证问题”的事件
- 标题和摘要不足以解释问题本质的事件

## signal 最小骨架

每个进入正文的 signal 至少补齐：

- `headline`
- `theme`
- `chain`
- `node`
- `problem_statement`
- `old_solution`
- `what_changed`
- `why_it_matters`
- `open_questions`
- `evidence_links`

## 写作规则

- 日报不要写成新闻列表
- 时间范围是否命中由查询层决定，不由大模型临场判断；默认优先使用 `报道窗口键`
- 先筛选，再写作；不要把原始新闻逐条翻成中文就当日报
- 每个 signal 至少说明：
  - 属于哪条链、哪个节点
  - 真正想解决的问题
  - 相比旧方案发生了什么变化
  - 还缺哪些关键证据
- 证据不足时，写“待验证问题”，不要写成定论
- 如果没有阅读全文，就不要写“判断更新”
- 在成品之外补一段简短过程日志，至少说明：
  - 读取了多少条原始新闻
  - 去重后剩多少条
  - 排除了多少条噪声/时间不可信记录
  - 最终进入正文的高价值事件有哪些

## 日报完成标准

一份合格的日报，至少同时满足：

1. 有 `今日新增信号`
2. 有 `分主题观察`
3. 有 `今日判断更新`
4. 有 `高优先级待验证问题`
5. 有 `关键原文链接`

## 早报完成标准

一条合格的早报导读消息，至少同时满足：

1. 开头包含当天绝对日期，默认地点为 `福州`
2. 语气温和、克制、有一点人文关怀，但不鸡汤
3. 包含 3 条最重要信号，每条解释“为什么今天值得先看”
4. 包含 1 个今天值得继续关注的问题，以及当天日报文档链接
5. 附上原始新闻多维表格链接，方便回查

## 投递规则

- 发群时直接用明确的 `chat_id` 发送成品
- 不依赖额外 announce / completion 通知
- 文档链接和导读消息都应明确发到目标群
- 群里发送的是成品，不是执行摘要
- 飞书私聊测试模式下，只发给当前发起人，不发群
- 但应在成品正文中包含一小段“过程日志/筛选说明”，而不是完全黑盒

## 原始表保护规则

- 默认只读原始新闻表
- 不批量更新、批量删除、重置记录
- 不把 signal、主题判断、归并结果回写到原始表
