# AI 新闻抓取 Skill

这个 skill 只做一件事：

`采集公开网页新闻 -> 标准化 -> 写入飞书原始新闻表`

它不负责：
- 生成日报
- 归并事件
- 写判断更新
- 发送早报消息

这些动作交给 `ai_news_reporter`。

只需要看这 4 份参考：

## 两种执行模式

### 1. 默认 cron 模式

这是生产模式，也是默认模式。

特点：

- 由 cron 自动执行
- 以无人值守为前提
- 默认不依赖 `exec` 审批
- 只做采集、轻量标准化、入表

要求：

- 生产链路必须能在没有人工确认的情况下完成
- cron 默认不要运行 shell、本地 python 脚本或浏览器
- 不能把“等待 exec 审批”作为 cron 的常态

### 2. 飞书补充模式

这是临时补抓模式，用于补充特殊场景，不替代 cron。

支持从飞书对话里注入这些参数：

- 指定网站/新闻源
- 指定时间范围
- 指定输出/存储目标

这三个参数都不是必填项，可以只传其中一部分。

飞书模式适合：

- 临时补抓某个源
- 验证某个源的采集效果
- 指定一个时间窗口补数据
- 指定把结果写到某个文件或目标位置

## 默认执行顺序

1. 列表页优先用 `agent-reach` 读取。
2. 直接从 `agent-reach` 结果中提取：`标题 / 原文链接 / 原始时间 / 原文摘要`。
3. 在本轮任务内做轻量标准化：只在时间文本足够明确时生成 `发布时间`。
4. 一旦完成写入就立即结束任务，不要再二次补抓或重写。

一句话：

`agent-reach 采集 -> 轻量提取 -> 入表`

## 默认原则

1. 只处理公开网页源，不把 RSS、公众号、Twitter 混进主链。
2. 采集阶段先保真抓原始字段，不在原始表里写分析结果。
3. 每条新闻只从同一条卡片提取：`标题 / 原文链接 / 原始时间 / 原文摘要`。
4. `原始时间` 原样保留；`发布时间` 只在本轮能可信确认时才写入。
5. `原文摘要` 不能重复标题；广告、推荐位、作者模板、无意义文案直接留空。
6. 只要时间、链接或来源不可信，就不要写入。
7. 友好抓取，少请求；遇到 403、验证码、登录墙、明显限流就跳过。
8. 默认 cron 模式优先保证稳定和可重复，不在运行时临时发明新流程。

## 采集任务硬约束

1. 采集任务只做“抓取并写入原始新闻表”，不要顺带生成日报、发消息、查整表、回写分析字段。
2. `发布时间` 不靠代理临场猜测；只有能可信确认的情况下才写入。
3. 无法可信确认 `发布时间` 时，只保留 `原始时间` 供后续排查，本轮不写入该条。
4. cron 默认不使用浏览器兜底采集，也不运行本地脚本；`agent-reach` 读不到字段就跳过该条。
5. 任务结束时只返回：`写入N条` 或 `0条写入`。

## 无人值守要求

如果这个 skill 作为 cron 默认运行链路，就必须满足：

- 不依赖飞书聊天内的 exec 审批
- 不依赖临时对话确认
- 不依赖浏览器手工补抓

当前推荐做法：

- cron 只走 `agent-reach` + 轻量字段提取
- 飞书模式只做补充，不承担生产主链

## 原始新闻表字段

默认写入：

- `标题`
- `原文链接`
- `来源`
- `来源类型`
- `发布时间`
- `原始时间`
- `原文摘要`
- `标题哈希`
- `摘要哈希`
- `处理状态`
- `备注`

补充：

- `原始时间` 保留网页原值。
- `发布时间` 由脚本标准化生成。
- `抓取时间` 不再写入，优先使用飞书创建时间字段。
- `摘要哈希` 只有在 `原文摘要` 存在时才写。

## 本地脚本

默认脚本链：

- `normalize_agent_reach.py`
- `build_source_items.py`

它们的作用不是替代采集，而是补充处理：

- 从 `agent-reach` 文本中提取结构化字段
- 时间标准化
- 摘要清洗
- 字段映射

补充：

- `fetcher.py` 保留为历史调试/排障脚本，不再作为默认主入口。
- 这些脚本更适合手动补抓或后续精修，不是 cron 默认入口。
